# V4 설계 노트 — 설계만, 구현하지 않는다

> **상태: 설계.** 코드 · 배포 없음. 지금 배포본(V3 계열 10종)은 그대로 두고, 12주 판정 뒤
> 한 번에 묶어 재배포한다(재배포하면 웹 · Unity 가 새 주소 · ABI 를 다시 굽는다).
> 출처: 품질 검토(2026-09-26) §3-C 의 "판정 뒤(V4)" 칸. 그동안의 임시 조치도 여기 함께 적는다.
> 바탕 원칙은 그대로다 — 재화만 거래 · 플레이 보상은 양도 불가 · 관리자 키 없음 · 체인이 정본.

## 0. 임시 조치 (재배포 없이 지금 한 것)

| 결함 | 임시 조치 | 남는 한계 |
|---|---|---|
| 리스팅 없는 `buy()` 가 가격을 강제하지 않는다(1 wei 로 쿠폰) | `scripts/list-brand-items.mjs` — 브랜드 품목마다 주인 주소로 `list(itemId, price)`(기본 예행, `--yes` 로만 보냄) | 주인 키가 있어야 한다. 리스팅된 품목은 흥정이 막힌다. 사용자 노점(`oc-`)은 `buyStall` 이라 이미 가격이 강제된다. 아무 문자열 itemId 로 아무 주소에 1 wei 구매하는 것은 여전히 된다 — 기록이 흐려질 뿐 금전 피해는 없다(테스트넷) |
| `release()` 를 부르는 곳이 없는데 화면이 '자동 정산'이라 했다 | 문구를 고치고, 판매 장부에 '정산 받기'(release) 버튼 | 판매자가 누르지 않으면 대금은 에스크로에 남는다 |
| 복주머니 등급 표기가 실제 확률과 달랐다 | 등급을 빼고 '여덟 가지 모두 1/8' 을 적었다 | reveal 폴백의 예측 가능성은 그대로(§6) |

## 1. 리스팅 없는 구매는 흥정(Offers)으로만

- `GiwaMarketV4.buy(seller, itemId)` 는 **리스팅이 활성일 때만** 받고, 값은 `msg.value == price` 로 강제한다.
  리스팅이 없으면 `NotListed` 로 되돌린다.
- 값을 정하지 않은 거래는 모두 `GiwaOffers` 를 지난다: 구매자가 값을 걸고, 판매자가 수락하면 체결.
- Offers 가 Market 을 부르는 길은 `buyFromOffer(seller, itemId, buyer)` 하나 — `msg.sender == offers` 만 허용
  (배포 때 한 번 고정 · 바꾸는 함수 없음). 이렇게 하면 "리스팅된 품목은 흥정이 막힌다"(V3 의 `GiwaOffers.sol:82`)도
  풀 수 있다: 리스팅 값보다 낮은 제안도 판매자가 받아들일 수 있다.

## 2. 정산 경로

- V3: 구매자 `confirm` · 누구나 `release`(24시간 뒤) · 분쟁이면 7일 뒤 · 판매자 `refund`. **자동은 없다.**
- V4 안: 판매자가 대금을 모아 받는 `withdrawReleased(ids[])` 를 둔다(가스 한 번에 여럿). 화면은 계속
  "판매자가 받아 간다"로 말한다 — 체인에는 타이머가 없으므로 "자동"이라는 말을 쓰지 않는다.
- 전자상거래법의 청약철회 7일과 24시간 창의 관계는 메인넷 전에 법률 검토(검토 §10).

## 3. 환불은 쿠폰을 태운다

- V3 `refund` 는 대금만 돌려주고 쿠폰(ERC-1155)은 구매자에게 남는다 — 돈도 쿠폰도 가진 상태가 된다.
- V4: `refund` 는 구매자의 그 tokenId 1장을 **태운 뒤** 대금을 돌려준다. 이미 선물 · 사용한 쿠폰이면
  환불 대신 분쟁 기록만 남긴다(`RefundBlocked`).
- 대안(더 단순): 쿠폰을 정산 전까지 **계약이 보관**하고, 정산 때 구매자에게 넘긴다. 환불이면 그냥 태운다.
  이 편이 코드가 줄어 규칙 3 에 맞는다 — **이 안을 기본으로 한다.**

## 4. 흥정의 에스크로 · 분쟁

- V3 흥정은 수락 즉시 `confirm` 까지 해서 에스크로 기간 · 분쟁이 없다.
- V4: 수락은 체결만 하고 정산은 일반 구매와 같은 경로(§2 · §3)를 탄다. "합의했으니 즉시 정산"은
  구매자가 스스로 확정하는 것으로 충분하다.
- 제안 만료(`expiresAt`)를 둔다 — 지금은 구매자가 취소하기 전까지 돈이 묶인다.

## 5. 메타데이터 URI · 목록 조회

- `uri()` 가 가리키는 `coupon/{id}.json` 이 없다. V4 는 **온체인 JSON(data: URI)** 으로 이름 · 판매자 · 테스트넷 표기를
  돌려준다 — 파일 호스팅이 필요 없다. 이름은 구매 때 저장한 itemId 를 쓴다.
- `openStalls()` · `offersFor()` 는 전체 이력을 돈다 — 쌓일수록 응답이 커지고 결국 RPC 한도에 걸린다.
  V4: `openStalls(offset, limit)` · `offersFor(seller, offset, limit)` 와 활성 목록의 swap-and-pop 색인.

## 6. 복주머니(GiwaBoxes) reveal 폴백

- 256블록이 지나면 `keccak256(b, sender)` 로 정해진다 — **열기 전에 계산할 수 있다.** 열 블록을 골라 원하는 결과를
  얻을 수 있다(무료 · 소울바운드라 피해는 작지만 "미리 알 수 없다"는 주석은 틀렸다).
- V4 안: 256블록이 지나면 결과를 주지 않고 **봉인을 무르고 쿨다운 없이 다시 열게** 한다(`expired → reopen`).
  결과는 언제나 열기 뒤의 블록 해시로만 정해진다.
- 확률표를 계약 상수로 두고 화면이 그 상수를 읽는다(지금은 여덟 가지 모두 1/8). 등급을 다시 쓰려면 표가 그걸 보여야 한다.

## 7. 도깨비 주 경계 vs 장날

- `week = block.timestamp / 7 days` 는 **목요일 09:00 KST** 에 넘어간다. 장날(토 21시 KST)은 주 가운데에 끼어
  "주의 끝에 몰아서 잡는" 이야기가 되지 않는다.
- V4: `week = (block.timestamp + OFFSET) / 7 days` 로 주가 **장날이 끝난 직후(토 22:00 KST)** 에 넘어가게 한다 —
  장날이 한 주의 절정이 된다. `OFFSET` 은 `GiwaHearth.isMarketDay` 와 같은 표에서 `npm test` 로 대조한다(CLAUDE.md §4).

## 8. 온기(GiwaHearth)의 동석 증명 — Sybil

- `claim` 은 "같은 창에 2명 이상이 `gather` 했다"만 본다 — 한 사람이 지갑 둘로 혼자 온기를 얻는다.
- 가능한 길(가벼운 순):
  1. 창마다 온기를 받을 수 있는 수를 `countOf` 에 비례해 줄이지 않고, **서로 다른 Dojang 인증 주소**만 셈에 넣는다
     (인증이 없으면 0.5 로 센다).
  2. 비컨 좌표(GiwaPresence)가 모닥불 반경 안에 있었는지를 함께 본다 — 여전히 위조 가능하지만 비용이 는다.
  3. 서로 서명(A 가 B 의 세션 글에, B 가 A 의 것에) — 실시간 서버 없이 되지만 UX 가 무겁다.
- 온기는 양도 불가 · 도깨비 타격 보정(최대 +20)뿐이라 **1번만** 권한다.

## 9. 재배포 순서 (그때가 오면)

1. `npm run test:local` 에 위 항목마다 실패하는 시험을 먼저 넣는다(anvil · 가스 0).
2. 배포 → `client/src/config/*.ts` 생성 → `npm run export-world` → `npm test`.
3. Unity `node tools/project.mjs bake` · `parity` 로 새 ABI 를 굽는다.
4. V3 의 쿠폰 · 칭호는 옮기지 않는다 — 테스트넷 기록으로 남기고 새 판에서 새로 시작한다(보존이 필요하면 V3 의 `legacy*` 패턴).
